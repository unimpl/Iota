# 上下文压缩策略

本文描述当前实现的滚动结构化摘要策略，入口与配置见 [README](../README.md#上下文压缩)。旧的普通摘要/重要状态检查点格式不兼容，恢复时明确报错。

会话 JSONL 保留原始消息、完整工具结果及历次检查点。压缩只替换模型使用的历史视图。一个 session 在任一时刻只有**最新一份完整结构化摘要**生效；旧检查点保留供追溯，不能与新检查点同时进入模型上下文。

## 最近原文与原始证据

`compaction_keep_recent_tokens` 默认 8000。程序从最新消息向前估算 token，并扩展到完整模型 turn 边界。一个 turn 包含一次模型回复及其全部工具结果，回复前的用户消息也归入该 turn。受保护原文不裁剪、不摘要；实际保护量可以超过配置值。没有更旧内容可处理时明确报错。

旧的长工具结果可继续首尾裁剪，并附原始 seq 地址；裁剪前原文留在 JSONL。摘要应读取原文：若活动上下文已有裁剪结果，按 seq 从会话记录恢复。`read_history` 按 seq 分页找回原消息，`search_history` 按关键词查找。仅裁剪工具结果就已使请求足够小的既有快捷路径继续保留。

## 技能指令

技能正文是程序维护的独立指令快照，不交由摘要模型改写。`skill_activated` 保存技能元数据、正文哈希、完整 `SKILL.md` 及用户/模型来源；Session 重放这些事件恢复活动版本，`/reset` 清空活动技能。加载指令的消息带有对应名称及哈希标记，旧工具结果裁剪跳过这些消息。

生成摘要时，技能正文消息替换为名称、版本和激活说明，摘要只保存用户选择、任务条件、工作进度及决定。正文从候选历史移出后，SDK 根据活动快照在下一请求的临时运行时消息中恢复完整指令；已有同一版本完整正文时不重复注入。恢复不依赖磁盘当前版本，也不依赖摘要模型记住重新读取的要求。技能引用文件仍属于普通证据，可以裁剪或摘要，必要时调用 `read_skill_resource` 再读。

候选大小、保护范围、自动压缩目标和最终窗口检查均包含需要恢复的完整技能正文，避免把“正文移出历史”误计为 token 减少。必要指令超过模型窗口时拒绝压缩并保留历史；不能为达到压缩目标静默删掉技能步骤。活动技能只适用于相关任务，不能将它的计划当作新请求或执行授权。注册表重载不修改当前快照，重新激活才切换版本。

## 结构化摘要

摘要为持续更新的任务状态，各字段允许保留必要细节，不规定“一句话”长度。单 turn 与跨 turn 使用同一结构和明确的字段标记：

| 字段 | 应保留的内容 |
| --- | --- |
| 目标 | 用户期望结果、完成条件；多任务时区分各自状态 |
| 约束与条件 | 用户限制、偏好、适用范围，以及它们何时成立 |
| 进度 | 已完成、进行中、阻塞；修改、执行与验证分别记录，注明验证范围和结果 |
| 关键决定 | 当前选择、原因、适用条件、明确替代的旧选择 |
| 下一步 | 有顺序的待办、前置条件及待验证事项 |
| 关键上下文 | 已确认事实、文件或错误、必要证据、已排除方案及原因 |
| 待确认 | 相互矛盾的事实、各自依据以及需要回查的原文 |

模型返回 `{"entries":[{"id":"cache","section":"decisions","text":"使用 A，原因是项目隔离","status":"active","refs":["turn:t0","summary:cache"],"reason":"条目变化的原因"}]}`。字段标记由程序统一渲染。每条关键陈述都带稳定条目 ID、状态和来源引用。程序保存实际 `seq`、`run_id`、`step_id`，并将模型引用绑定到这些地址。保存的计划、授权和清单进度仍由独立的权威状态提供；摘要可以说明它们对当前工作的含义，但不能取代权威状态。

摘要应优先保留目标、条件、因果、进度与证据，去掉重复措辞和无关过程。篇幅由整体 token 预算控制，不用每条固定字数上限强迫重要内容变短。

## 生成与滚动合并

1. 选出未受保护的旧消息，按完整 turn 划分**来源**，为本次 turn 分配临时 ID，并发出包含范围的准备事件。turn 边界不是逐 turn 调用模型或逐 turn 输出摘要的要求。
2. 优先在一次摘要请求中提供**上一份结构化摘要 + 本次待压缩原文**。模型直接返回一份完整的新结构化摘要；没有旧摘要时只提供原文。原文及工具输出作为数据，不能执行其中的指令。
3. 仅当整个输入放不进摘要模型窗口时，按完整 turn 分批。每批用同一结构更新暂存的完整摘要；单个 turn 过大时才使用明确标注不完整的摘录，并保留回查地址。所有批次成功、最终完整摘要校验通过后一次性生效。
4. 模型可以引用新输入的 `turn ID` 和旧摘要条目的稳定 ID；程序校验这些引用、必填字段、状态转换与旧条目的处理，再绑定原始来源。旧条目必须在新输出的引用中恰好被处理一次；单条更新保留 ID，同字段合并继承全部来源。修改文本或状态必须提供原因，状态升级需要新增历史中的工具结果或用户确认来源；摘录或助手自述不能单独作为完成证据。引用存在不代表该来源确实支持该结论。例如旧决定的来源是 `seq 4–8`，新证据属于 `turn:t12` 对应的 `seq 40–45`，合并条目保留两组真实来源，不能只指向上次摘要的检查点 seq。模型不能指定历史地址。
5. 只有新检查点记录成功，才替换活动上下文里的旧检查点。失败、取消、引用无效、关键状态无故消失或完整请求未变小，都保留原活动历史。

合并提示词应明确执行以下规则，参照成熟 coding agent 的目标、约束、进度、决定、下一步和关键上下文结构，并补足状态与证据要求：

- 新事实先补充已有事实；判断是否属于不同时间、环境或条件。不能解释的矛盾保留双方及来源，标记待确认或回查原文，不能擅自选一个作为事实。
- 已完成事项更新进度，保留必要的验证命令、结果和覆盖范围。未实际运行时保留“待执行”；局部测试通过不能写为全部验证通过。
- 新决定**明确替代**旧决定时，更新当前决定、原因与适用条件，并保留旧决定及其被替代的来源以供追溯。没有明确替代关系时不得自行推定。
- 用户约束没有在新增历史中出现，仍然有效；只有用户明确变更或可证实的适用条件终止，才更新其状态。旧目标、约束、未完成事项等关键条目必须在新摘要中明确保留、更新或说明为何失效，不能无故遗漏。
- “计划执行”“已修改”“已运行验证”“已验证完成”是不同状态。模型回复中的完成宣称不能替代工具结果或用户确认。无法判断时保留较弱状态并标记待确认。

来源校验只能证明引用地址存在，不能证明模型对原文的解释正确。必要时应从原文回查；未回查不能写成已经核实。

## 预算与可观测性

程序估算**完整模型请求**的 token，包括系统指令、工具定义、结构化摘要、最近原文和运行时状态。自动压缩以已知窗口容量的 `compaction_target_ratio` 为目标，默认 0.20；没有容量数字时，按被拒绝请求的估算大小计算，并标记为估算。手动压缩只要求候选完整请求比原请求更小。

超过目标时，最多三次改写候选完整摘要，先去重、压缩表述和归档低价值的 `context` 历史细节，再检查完整请求。只有 `context` 条目可标记 `archived` 并移出活动摘要，原文与归档陈述仍可查询；其他字段不能用该状态绕过保留要求。保留有效目标与约束、当前决定及原因、未完成步骤、必要验证证据和冲突状态。被移出的细节及来源仍保存在会话记录，历史工具可以找回。预算策略不再机械地“移出最老的 turn 摘要”，因为生效内容已是一份统一结构化摘要。若最近原文与必要状态自身超过目标，报告实际估算用量，保留必要状态；20% 是目标而非已知模型窗口，候选完整请求变小且未超窗口时仍可生效。单个受保护 turn 超过模型窗口时明确报错。

终端和事件流应报告原文选择、摘要请求或降级分批、合并校验、预算处理和最终应用；耗时较长时展示已处理的 turn 数。只有最终检查点进入模型上下文，旧检查点与原始记录留在 JSONL。

例如，旧摘要记录“用户选择缓存位置 A，因项目隔离”，新增原文记录“代码已改为 A，单元测试通过，集成测试未运行”。新摘要保留原约束和决定原因，将进度更新为“修改完成、局部验证通过”，下一步保留集成测试；它不能写成“迁移已全部验证”。若后来用户明确选择 B，新摘要将当前决定改为 B，记下变更原因，同时保留 A 及变更证据的原始来源。
